# Halyk AI Hackathon - проверка ковенантов по кредитным договорам

Решение, сделанное в одиночку (команда `onemanarmy`) на хакатоне Halyk AI.

## Задача

На входе был набор документов по заёмщикам (кредитные договоры, аудиторские примечания, годовые отчёты, KYC-досье в PDF, DOCX, XLSX и TXT) и леджер транзакций за 2025 год (`master_ledger_2025.csv`, около 2 350 операций в USD и EUR).

Для каждого сценария (заёмщика) из `submission_template.json` и каждого пункта договора (6.1, 6.2, 6.3) нужно было определить:

| Поле | Что это |
|---|---|
| `status` | `COMPLIANT` или `BREACH` - выполняется ли ковенант |
| `actual` | фактическое значение показателя, посчитанное по леджеру |
| `evidence_txn_id` | транзакция-доказательство нарушения (для агрегатных тестов - `null`) |

## Как работает решение

Пайплайн состоит из двух частей: LLM достаёт условия из документов, а сами расчёты делаются обычным кодом по леджеру, чтобы модель не "считала в уме".

1. Чтение документов (`read_file_text`): pdfplumber для PDF, python-docx и docx2txt для Word, pandas для Excel.
2. Фильтрация: документы без явных ссылок на пункты и слова "ковенант"/"covenant" не отправляются в модель. Документы с пометкой "недействующая редакция"/"superseded" пропускаются, чтобы не взять старые лимиты.
3. Regex-подсказки: account_id (вида `ACC-7301`), упоминания транзакций, переклассификаций и валютных курсов - для ручной проверки.
4. Извлечение ковенантов локальной моделью `Qwen/Qwen2.5-1.5B-Instruct` (transformers). Модель возвращает JSON: номер пункта, тип правила, лимит и период. JSON чинится через `json_repair` и проверяется pydantic-схемой.
5. Привязка документа к сценарию: по леджеру строится соответствие `account_id -> scenario_id` (по префиксу `TXN-<сценарий>-`), поиск по тексту документа - только как запасной вариант.
6. Расчёт по леджеру (`evaluate13.py`): суммы в EUR переводятся в USD, затем проверяется правило нужного типа: `max_expense`, `min_revenue`, `min_quarterly_revenue`, `max_single_tx`, `min_balance`, с учётом периода из договора.
7. Результаты пишутся в `submission.json`, ответы модели кэшируются в `extracted_cache.json`, чтобы не гонять LLM повторно.

## Результат

Финальный `submission.json` заполнен для 63 из 84 ячеек шаблона. Из 304 обработанных документов ковенанты были найдены в 21.

Известные ограничения: курс EUR/USD захардкожен (1.08) вместо курса из документов датасета, маленькая модель (1.5B) иногда пропускает ковенанты или путает тип правила, нестандартные ковенанты (коэффициенты, агрегатные лимиты) сводятся к ближайшему типу.

## Запуск

Папка `documents/` с исходными документами в репозиторий не входит, её нужно положить рядом со скриптами.

```bash
pip install torch transformers pdfplumber pandas openpyxl pydantic json-repair python-docx docx2txt
python main11.py
```

Модель скачивается с Hugging Face при первом запуске, работает на GPU и на CPU (медленно).
